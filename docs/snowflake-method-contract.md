# 雪花方法契约（Snowflake Method Contract）

状态：**现行契约**（2026-09-13 阶段 A–G 落地后核对）。本文把构思模块的十步、场景形态、闸门与失效规则逐条对照原著，写清项目字段、哪些是硬闸门、哪些是有意的差异。代码与本文冲突时以代码为准，并回写本文。

来源：Randy Ingermanson，《How to Write a Novel Using the Snowflake Method》（第 19–20 章的十步定义与 Goldilocks 示例）与《How to Write a Dynamite Scene Using the Snowflake Method》（主动 / 反应场景、坩埚、场景分诊）。本文只借鉴方法，不复制原著文本。

## 0. 三条原则

1. **指南而非规则。** 原著反复强调步骤可跳、可回退、可改顺序。规则层只拦「缺失」与「占位」（空字段、等于提示语、含 待补/TODO），质量判断交给 LLM 分诊与作者，并且永远可覆盖：验收门未过也可确认本步，后端闸门只守依赖顺序。
2. **提示词、归一化、诊断说同一句话。** 任何一处要求的长度、段数、字段，其余两处不得截断或判弱。数量契约（五句、五段）在生成侧以 `StructuredCountMismatch` 拒绝并重试一次，从不静默截断。
3. **设计成果必须到达写作。** 第 9、10 步写下的形态、坩埚、三拍与代价，起草、蓝图、硬软 QC、近终稿评审都能看到带标签的版本（`Scene Structure (Snowflake)` 段），不是无名节拍。

## 2. 场景形态

- **主动场景**：目标 → 冲突（多轮尝试受阻、逐级升级）→ 挫折。挫折**以主角衡量**：POV 是对手时，对手得手就是主角的挫折；胜利必须带主角持续支付的代价。
- **反应场景**：反应（先在身体上、先于分析）→ 两难（每个选项都有代价）→ 决定（直接生出下一场的目标）。
- **坩埚**：把 POV 困在这一场、让他不能一走了之的力量。每场必填。
- **一场挫折之后三选一**：切到另一条 POV 线、直接开下一场主动场景、或只在下一目标不明显时写反应场。反应场是少数，不要机械交替；场景类型默认主动，不按行号奇偶。
- **反应场的呈现**：`rendering_mode = full | summary`。`summary` 只对反应场合法，物化后篇幅带为 200–500 字，起草模板用两三段叙述性概述写反应、两难、决定。原著的第三个选项「略过」没有建模——直接在场景列表里删场表达。
- **写完之后的分诊**：近终稿评审对每场回答「坩埚在正文里认得出来吗、设计的三拍落地了吗」，并给 Yes / No / Maybe 一句话（`scene_story_check`）。它只提示不阻断，随评审记录持久化，目录与成稿中心按场显示。

## 3. 闸门与失效

- **硬闸门**（结构物化前必须满足）：01、02、03、09、10。其余步骤缺失只产生警告。跳过需要给原因，跳过的步骤视为「已满足」进入下游上下文。
- **验收门是指南**：右栏的机器核验与人工清单只是自检；「确认本步」始终可点，后端 `approve` 才守依赖顺序（前序未确认时静默保持待批准，并在补齐后自动批准）。
- **失效（stale）的单一真相在后端**：`snowflake_staleness.FIELDS_CONSUMED` 登记每步**直接展开**的上游及其被读的字段（01→02 不含安全规则；03→04 / 05；04、05→06；05→07；04、06→08；07→09；09→10）。上游被消费的字段一改，下游确认过的步骤置 `stale` 并记 `stale_reason`；本步不消费的上游怎么改都不亮（变化经真正的下游一层层再批准来传递）；点过「已复核」的步骤在上游再改时重新亮起。09 重新批准只把内容真的变了的场景计划置 stale。前端不再保留第二套失效算法（E3 第二步已移除本地 revs 图）：只读后端的 `stale` 与 `stale_reason`，并按本步 `input_refs` 对照各上游当前的 `step_run_id` 给出「哪些上游已有新版本」的方向提示。
- **改动已确认的步骤 = 待重新确认**：后端在步骤载荷上给 `revised_after_approval`；前端不再在停止输入一秒后自动补批准，而是显示「已改动 · 待重新确认」，等作者点「确认本步」——下游失效级联在那一刻发生，不在打字时。
- **物化之后回溯不毁正文**：01 / 02 / 03 / 05 重新确认对运行时只是提示（`scope=advisory`），已有草稿、QC、终稿全部保留，新设计经 `Scene Design Context` 段在下一次起草自然到达；09 只失效内容变了的场，07 只失效章表行变了的章里的场；10 与角色三步按场定位（原有）。
- **回溯是廉价的**：stale 横幅提供「查看上游改了什么」（按本步确认时消费的 `input_refs` 对照上游历史版本）、「按新上游重新展开」（用现在的上游材料重新生成本步，生成前留底）、「已复核」（在服务端 `accept-stale` 留痕，并把消费的上游版本刷新到当前——「仍然有效」是对现在的上游说的）。批准与复核的回包都带整份工作台，下游的失效状态即时可见。

## 4. 有意不做的事

- 不做自动出版裁决：任何评分、分诊、验收都只提示，作者拍板。
- 不建模「略过反应场」的呈现方式（见 §2）。
- 不给章表以外的地方第二套章结构；不给前端第二套失效算法（E3 第二步已移除本地 revs 图）。
- 不复制原著文本、示例人物或桥段；Goldilocks 示例仅作为测试金标准的译写形态存在于 `backend/tests/test_snowflake_method_contract.py`。
