# AI 小说创作系统操作手册

> 适用于正式 React 工作台 `frontend-react/`，核查日期：2026-08-19（第 4 节「风格参考」：2026-09-23）。
> 本系统面向受控的单机、单作者工作流，不是多用户 SaaS、自动出版裁决器或跨设备备份服务。

## 1. 启动与停止

环境要求：Python 3.12、Node.js/npm。首次使用先安装 React 前端依赖：

```powershell
cd frontend-react
npm ci
cd ..
.\start-dev.cmd
```

默认地址：

- 正式 React 工作台：`http://127.0.0.1:5174`
- 后端：`http://127.0.0.1:8000`
- 存活检查：`http://127.0.0.1:8000/live`
- 就绪检查：`http://127.0.0.1:8000/ready`

启动脚本会先升级数据库，再启动后端与 React 前端。端口冲突时会选择可用端口，并把实际地址写入 `.codex-run/`。日常使用以下命令管理进程：

```powershell
.\stop-dev.cmd
.\restart-dev.cmd
```


## 2. 界面结构

工作台默认进入 `主页`。左侧底部可切换 `作家` 与 `高级` 模式；切换只改变可见入口，不改变数据和生成结果。

作家模式包含：

| 入口 | 用途 |
| --- | --- |
| 主页 | 查看当前作品、进度、全书各章所在阶段、风险和下一步动作（原「流程」页已并入）。 |
| 构思 | 完成雪花十步、场景急救、结构物化与后续回流。 |
| 写作 | 人工编辑、生成 AI 候选、保存草稿并提升权威正文；深改姿态是一场诊断的唯一展示处（规则体检、节奏、起草评审、AI 深评合成一份，忽略按发现记；有风格绑定时规则按参考书校准；「AI 看这一处 / 这几段」对着整场看，能指出跨段的矛盾）。 |
| 风格 | 三步：参考书 → 学习文风 → 用于作品，外加第四步「对照检查」（见第 4 节）。 |
| 待办 | 处理系统生成的人工决策、阻断和风险卡片。 |
| 资料 | 管理人物、世界、事件、关系和时间线资料。 |
| 设置 | 配置供应商、模型、额度和界面偏好。 |
| 回收站 | 恢复软删除对象或执行明确的永久清理。 |

高级模式额外显示：

| 入口 | 用途 |
| --- | --- |
| 章节编排 | 全书结构（卷 → 章 → 场）、章节详情与戏剧卡；`整理章节结构`（与构思里的是同一张分章面板）；启动持久化整章任务。 |
| AI 起草台 | 左栏是全书书脊（与目录同源）；按场景运行生成管线，观察真实状态、失败和恢复。 |
| 成稿中心 | 通读服务端正文、绑定正文哈希、批准或重开终稿；「诊断」页签：AI 通读本章（章级判断落到各场；改过几场就能「只通读改过的 N 场」）与每场开着的诊断发现数。 |
| 文学质量 | 全库巡检同一份规则发现（与写作台深改面板同一条、同一个 id，在写作台忽略过的不再列出）；分数不等同于出版质量或读者偏好。 |
| 成本看板 | 查看 LLM 请求、token 与费用估算。 |

`Ctrl+K` 可打开命令面板。直接访问高级视图的哈希路由时，工作台会自动显示高级模式。

完整恢复使用第 6 节所述数据库工具；浏览器本地恢复记录不是服务端备份。

## 3. 推荐创作主线

```mermaid
flowchart LR
    A["新建作品"] --> B["雪花十步"]
    B --> C["场景急救"]
    C --> D["整理章节结构"]
    D --> E["人工写作或 AI 起草"]
    E --> F["作者复核并提升权威正文"]
    F --> G["核对正文事实并提交正史"]
    G --> H["成稿通读与哈希确认"]
    H --> I["批准终稿与长篇检查"]
```

### 3.1 新建作品

从顶部作品切换器选择 `新建作品`，填写书名、题材、一句话简介、目标字数和主色。章节规模与更完整的故事结构在创建后通过作品设置和雪花构思继续完善。新作品使用真实后端项目，不会继承 `潮汐档案` 的人物、剧情或候选种子。

### 3.2 完成构思

进入 `构思`，按顺序处理十步雪花：

1. 读者定位
2. 一句话概括
3. 一段话概括
4. 角色摘要表
5. 一页梗概
6. 角色背景
7. 长篇大纲
8. 角色全档案
9. 场景列表
10. 场景规划

每一步都可以自己写，也可以用编辑页顶部的 AI 工具条：「AI 生成本步」按上游材料和本步要点直接写；「先看 3 个方向」让教练在教练页给三个不同走向，挑一个「按此生成本步」（02 一句话概括是自由文本，方向卡上直接「就用这一句」）；教练页的「本步要点」记着你在对话里定下的、否决的、约束的、还在犹豫的，AI 生成、方向和分诊都照它写，你可以逐条改写、撤下、加条，也可以关掉「继承上游」。要点改过而本步草稿还是按旧要点写的，工具条会提示「按最新要点重新生成」。教练的回复可以「按此生成本步」，你明确要它改写时它会给一版可「填入本步」的改写。允许带原因跳过部分步骤，但读者定位、一句话概括、一段话概括、场景列表和场景规划是结构物化前的硬检查项。这一层的完整契约见[雪花构思 · 教练、要点、方向与生成](snowflake-coach-and-directions.md)。

构思页底部的同步状态若显示「读不到服务器上的构思版本，已暂停上行以免覆盖服务器内容；本机版本已保留」，说明这次打开页面时没能读到服务器上的版本：此时系统不会把本机内容写上去（换了浏览器或清过缓存时，本机可能只是一份空白稿），后端恢复后点「重试」即可。万一某一步被整步清空，服务器会把清空前的版本留在该步的历史里。

第 10 步每一场除三拍与坩埚外还有：题名（留空跟随 09）、篇幅（短 / 中 / 长或自定义字数区间，如 800-1200）、必须出现（对话片段 / 物件 / 一句话）、呈现方式（完整场 / 概述两段；反应场另有「略过」）、破例理由（这一场故意不按三拍走时写下理由，规则层就不再把缺的三拍算缺失）。「AI 分诊」按原著的 Yes / No / Maybe 判每一场；「你的裁定」四档（通过 / 需修补 / 该重写 / 待删）由作者拍板并写回服务端——标为该重写或待删的场整理时不建场景卡、已建的卡回流进回收站，但不阻断其余场景。成稿中心「结构」页的场景三问徽章可「回第 10 步」改设计再重写，判 No 的场还可「标待删」（回收站可恢复）。

右栏的「验收门」是自检指南，不是锁：验收未过也可以点「确认本步」，后端只守依赖顺序（前序步骤未确认时保持待批准，补齐后自动批准）。确认过的步骤再改动时会显示「已改动 · 待重新确认」，不会在输入时自动重新批准；改好后再点「确认本步」，下游步骤才按新版本核对失效。改了上游步骤之后，下游已确认的步骤会出现「需复核」横幅：可以「查看上游改了什么」（对照本步确认时消费的上游版本与现在的版本）、「按新上游重新展开」（用现在的上游材料重新生成本步，生成前留底，生成后再确认），或核对无误后点「已复核」——后端标记的失效会在服务端留痕。各步与原著的对照见[雪花方法契约](snowflake-method-contract.md)。

完成场景列表和规划后运行场景急救，逐项处理 `合格 / 需修改 / 废除重写`。系统建议是诊断，不替代作者决定；未解决的重写项可能阻断物化。

### 3.3 整理章节结构

点击 `整理章节结构` 打开分章预览面板。确认之前什么都不落库；面板打开时按现状给出最诚实的一种分法：

- **按场景分章**（没有章表、或 07 里只有几行「（待补）」占位时的默认）：章是列完场之后的包装决定。三个灾难各自收束一章（09 的「脊柱」栏标了灾一 / 灾二 / 灾三，或者「功能」栏里写着「灾难一」都认），其余顺着场景列表按「每章约 N 场」切开。N 可以直接改，旁边写着默认值从哪来（参考书的章长 / 作品设置的目标章数 / 默认每章 3 场）；三个灾难决定了最少章数，填得再大也不会少于它。
- **倒进 07 章表**（07 里有你自己写的章表时）：同一个灾难标记的场与章互相锁定，其余按顺序铺开；也可以选均分。
- **已保存的分章**（分过章之后的默认）：上一次确认的结果原样摆出来，新加的场跟着场景列表里它的前一场走——不会每次打开都重算一遍。

**章是场景列表上连续的一段**：场的先后只有一个来源，就是 09 场景列表（那张可以拖动的表）。所以面板里每一场都带着它在场景列表里的序号和功能标签，能做的调整只有三种——章的末场移到下一章 / 首场并入上一章、从某一场「另起一章」、「并入上一章」——想改场的先后，回 09 拖行。章名可以直接在面板里改；章摘要默认取章末那一场（「这一章把局面推到哪」）。如果面板提醒「某一场排在前面几章的场之前」（通常是分章之后又在 09 拖过行），点提醒旁边的「按场景重新分章」。

**AI 起章名**：按场景分出来的章只有占位名「第 N 章」。面板上的「AI 起章名」给这些占位名各起一个名字、写一句章摘要（章摘要一栏就在章名下面，可以直接改）；你自己起过名字的章它不碰——想让它重起某一章，先把那一章的章名清空。结果只回到面板里，`确认写入` 时才落库；需要先配好模型，没配好会如实提示。章多的书一次起不完时，再点一次接着起。重新按场景分章时，场完全没变的章沿用原来的章名、章摘要和身份，只有真的变了的章才回到占位名。

点 `确认写入` 才物化：创建真实的 `ChapterGoal` 与 `SceneCard`，07 的章节表同步成确认的这一版。章节目录里如果已经有你手建、并且真的动过笔的章（起过名、写过字、填过一拍），它们原样保留、不会被覆盖：雪花的章按章表的顺序排，手建的章原来排在最前面的还在最前面、原来跟在哪一章后面的还跟在那一章后面（面板会提醒，不要的到章节编排里删）。只有一种手建章会被系统挪走：一个字没写、章名还是系统起的「第 N 章」、章下只有那张空白的「开场」占位场的章（通常是雪花做完之前先点过一次 `创建第一章 · 开场` 留下的）——它会在确认写入时移入回收站（面板事先说明，回收站里可以取回），这样雪花的章从第 1 章排起，而不是挂在一张空白章后面。**一章就是一章，不是「第几章」。** 目录里的每一章钉在章表的那一行上：拆章、并章、换一个每章场数之后，场至少一半还在的章仍然是目录里的同一章（从正中对半拆开时，前半截留着原章；两章等长地并成一章时，靠前的那一章留着；一章被整个拆成几小段、谁都不过半时，开头那一段留着原章，几章整个并成一章时开头那一章留着）——它的章名、你夹的「当前章」书签、章的状态和已经写下的东西都跟着它走，只是排第几变了；真正新出现的章才是新的一行，插在章表里它该在的位置。重新分章后再确认一次，只有真的换了章的场才会搬；搬的时候这一场写过的稿、定稿、待办也跟着换章，你在章节编排里手加的场跟着它原来的前一场走（前一场换了章，它也跟过去）。章名只有一个：在分章面板、07 的章节表、章节编排里改的是同一个名字，改完三处同时变（见下面「章节编排是分章的第二扇门」）。场被分光的旧章会自动移入回收站（确认后的回执里会说移走了几章，回收站里可以取回、也可以清空）；里面还留着东西的章（回收站里的场，或整章只有你手加的场）、已经终审通过的章原样保留。一章留在章表里、场被挪空之后又挪回来时，回收站里的那一行会被自动取回。目录里有已终审的章、而按章表排序会挪动它时，这一次不排章序——新章暂时接在最后，回执会提醒你到成稿中心重新打开后再整理一次。

确认写入之后，构思页顶部会出现一条交付条：目录现在是几章几场、顺手移走了什么，以及 `去写作台`（落在现在该写的那一场上）/ `去 AI 起草台` / `章节编排` 三个去处。写作台的大纲、AI 起草台的书脊、章节编排的看板读的是同一份目录，每一场都带着它在构思里的整张设计卡。

**章节编排是分章的第二扇门**：哪几场归哪一章、章的先后、在第几卷，只有一个编辑器——分章面板。它不只挂在构思里：章节编排的页头、章节详情的「构思里的这一章」条、右栏和全书体检里都有 `整理章节结构`，开出来的是同一张面板，确认写入后目录跟着变；反过来，构思第 9 步场景列表里的章头点一下也是这张面板，面板里每一场有一颗小笔直达第 10 步的那一场。所以雪花整理出来的章在章节编排的看板上不能拖（抓手是个固定标记；你手建的章照常拖，可以插在任何两章之间）。章名可以直接在章节编排里改——分章面板、07 的章节表、09 的章头会同时变成这个名字，「AI 起章名」也就不会再给它起一遍；把章名清空会落回 `第 N 章`。章节详情里的入口 / 出口、视角 · 时空不用填：它们取自这一章的首尾两场和各场的 POV / 时间 / 地点；全书编排的第一张图是全书结构（场上的数字就是构思里的场次）。删除一章雪花的章只是把目录里的章和场景卡移入回收站——构思里的分章还在，下一次确认写入会把这些场取回；想并章 / 拆章用面板，真不要这几场到构思第 9 步删行。

**确认即同步**：物化之后再改 09 / 10，点 `确认本步` 的那一刻，目录里的场景卡就跟上这一版构思（回执会说同步了几场），写作台和 AI 起草台立刻读到新卡，不需要再去点一次同步。只有一种卡系统不自动动，留在顶部的 `同步到目录` 横幅里让你先看差异：同步会把一张已经写过东西的场送进回收站（略过 / 该重写 / 待删）的卡。**设计只有一处可改**：雪花整理出来的场（构思里那一行还在），它的形态、三拍、POV、离场变化、钩子和彼此的先后只在构思第 9 / 10 步改——章节编排里这些格子是只读的（行上有 `在构思里改` 直达那一场），也不能拖动换序、不能切换主动 / 反应，章节规划 AI 不往里填；题名、状态、删除、交给 AI / 自己写照常。你手加的场、以及构思里已经删掉那一行但因为写过字被你留下的场，设计就在章节编排里改。这样构思和目录永远说的是同一件事，不会出现「台子上改了一版、构思里又是另一版」。要搬去的章目录里还没有的场，内容照常同步，只是暂时不搬——先 `整理章节结构`。台子上看到某一场标着「构思已更新」时，也可以直接在那张设计卡上点 `同步这一场`。不要手工制造第二套结构。

### 3.4 写作与 AI 起草

有三种常用入口：

- `写作`：适合人工起草、局部 AI 候选、编辑和版本冲突处理。进来时落在「现在该写的那一场」上（当前章里在写的那一场，否则第一场没写完的——主页的「继续写作」、AI 起草台的落点是同一条规则）。正文上方和右侧 `上下文 · 戏剧` 里是这一场的设计卡：坩埚、POV / 时间 / 地点 / 出场、按形态命名的三拍（反应场是 反应 / 两难 / 决定）、后续三拍、离场变化、钩子、读者感受、代价、必须包含 / 隐瞒，以及所在章的章摘要与脊柱标记。雪花整理出来的场可以从卡上 `在构思里改`（回第 10 步并对准这一场），手建的场是 `编辑卡`（去章节编排）。空白页就是空白——场景卡不再被抄成一段「【章节目标】…【节拍】…」塞进正文。
- `AI 起草台`：左栏是全书的书脊（章 → 场，与写作台大纲同一份目录），不需要先「加入场景」。点任何一场，中间就是它的预检清单和同一张设计卡，点 `开始起草` 即进入管线。只是点开看看的场不算 `在办`；交给 AI 的（`整章入列`、写作台 / 章节编排 / 待办里的 `交给 AI`）、开始起草过的、跑过管线的才是，左栏的 `在办` 筛选只留它们。适合逐场运行真实生成管线并观察每个阶段。用了风格参考的作品默认「作者手笔直起」：首稿直接以参考作者的手笔写；系统量一量首稿像不像这位作者，在作者的正常范围内就直接用，越界时只改不像的那几个维度、改完再量，不更像就保留首稿（见第 4 节）。在「风格 · 用于作品」里可切到「先中性后润色」作阅读对照。
- `章节编排` 的 `运行本章`：适合按章节启动持久化任务。

模型未配置、额度不足、内容阻断或后台失败会明确显示，不会静默切换为离线演示。AI 候选不会自动成为权威正文；作者必须先审阅，再执行提升动作。

### 3.5 成稿与终稿批准

在 `成稿中心` 批准终稿前，必须：

1. 确认项目所需章节和正文完整。
2. 打开“正史”页签，对当前终稿的事实候选逐条接受或拒绝；无论模型返回候选还是空结果，最后都要通读正文并明确确认候选清单没有漏项。
3. 确认章内所有场景的正史状态均已完成。
4. 打开并通读当前服务端正文。
5. 对当前正文哈希执行明确确认。
6. 再执行项目级终稿批准。

候选事实即使已逐条接受，也要等整场完整性核验后才会原子进入下一场上下文；正文换版后旧核验自动失效。目录标签和历史 `synced` 标记都不能伪造批准状态。批准后正文受到写入保护；若要重开，必须填写原因，系统会留下审计并撤销受影响的后续批准链。详细规则见[正史连续性与长篇记忆](canon-continuity.md)。

### 3.6 删除与批量删除

| 入口 | 可删对象 | 动作 |
| --- | --- | --- |
| `章节编排` · 全书编排 | 章节 | `多选` 后勾选章卡，`删除所选` 一次提交。 |
| `章节编排` · 章节详情 | 本章场景 | 场景看板 `多选` 后 `删除所选`；单场仍可用行尾删除按钮。 |
| `写作` · 章节大纲抽屉 | 章节、场景 | 章行悬停出现删除按钮；抽屉顶部 `多选` 可跨章勾选章与场后一次删除。 |
| `AI 起草台` · 书脊里在办的场 | 在办清单的成员 | 行内 `移出`，或 `多选在办的场` 后 `移出所选`。 |

多选是一个独占模式：进入后该区域只保留与选择有关的动作，新建、切视图、行内编辑与单条执行按钮全部收起，避免同一次点击有多种含义。点 `完成` 退出。

规则：

- 章节与场景的删除是软删除，进入 `回收站` 后可恢复；永久清理只在回收站里手动执行。删除后页面底部会给一条回执，说明删了几条并提供 `打开回收站`。
- 已批准终稿不可删除，勾选框会被禁用；需要改动请先在 `成稿中心` 重新打开该章。
- 删除一章时，章下场景随章一起回收；在写作台大纲里勾选整章后，章下场景会显示为「随章带走」且不再单独计数。
- 若某章下先前已单独回收过场景，后端会挡下整章删除，界面会显示原因并把该章放回目录，不会假装删除成功。
- `AI 起草台` 的 `移出` 只影响在办清单，不删除场景卡，也不删除已生成的 AI 稿——这一场仍然在书脊上，只是回到「待起草 / 已完成」的普通一行。因为不破坏任何东西，它不弹确认框，而是移出后给一条带 `撤销` 的回执；再次交给 AI（或重新开始起草）同样可以回到在办。正在运行的场不能移出，请先中止或等它跑完。

## 4. 风格、待办与资料

### 风格参考

`风格` 页只做一件事：让 AI 用一位参考作者的手笔写你的故事。雪花构思只提供框架（发生什么、谁、因果、顺序、视点），怎么写、什么气质以参考为准；系统只学写法，不复刻原文、人物或桥段。应只导入拥有分析和发送权限的文本；路径导入默认关闭。系统的本地相似度和规则不能代替版权清查，商业发布前仍需权利台账和法律复核。

页面左栏是参考书库（窄屏时收进页头的「参考书库」），右边是选中那本书的三步与第四步「对照检查」，步骤条标着每一步的状态（已完成 / 进行中 / 需处理 / 未开始 / 等前一步），打开时自动落在这本书下一步要做的地方：

1. **参考书**：`导入参考书`，选择或拖入 txt / md（≤10 MB），书名按文件名自动填入（可改），作者可不填；选「原文能发到哪里」——`仅本机模型`（正文只交给本机模型：分类、学习、起草、评审都要本机模型；哪一步的节点走云端，那一步就停下提示你，不会把这本书的任何东西送出去）、`起草不发原文`（分类和学习时，云端模型要分批读整段正文；起草、改稿、评审时只送文风卡，卡上的例子至多 11 个字、不含本书专名，不送原文段落）、`可发送全文`（起草时也带原文样例，最像）；默认选中的是按当前模型推荐的那一档。再勾权属声明（分析权必勾，不是「仅本机模型」时还要勾发送权）。导入后每一段都由模型标上类型（叙述、对话、心理……），这是后台作业，大书可能要较长时间，可取消，失败或中断后「继续分类」。这一步还显示段落分类的来源与一致率、段落类型分布和语料够不够；旧版导入的书如果段落类型大多是旧规则标的，会提醒你「用模型重新分类（保留画像）」——先报费用（调用次数 / token / 分钟）再确认，正文、文风画像和用在作品上的设置都保留。同一份文本重复导入会直接提示「打开这本」。书库里点 `选择` 可以勾多本 `删除所选`（确认框会列出书名和正在用它的作品）。
2. **学习文风**：一个按钮、一个后台作业——整理全书片段 → 挑样本（全书各处约 12 个连续片段、共约 4 万字）→ 分层读原文 → 写文风卡 → 识别本书专名 → 给全书片段打场面 / 情绪标签 → 写入画像。开始前给估算（调用次数、每层读多少原文），在跑时有进度、可取消，失败或取消后可「继续学习」。「重新学习」是就地更新同一份画像：用在作品上的设置和你的 ✓ / ✗ 都保留；段落类型更新过、正文变过或还是旧版画像时，页面会建议重新学习。下面就是**文风画像**：最前面是「气质 · 每场都要体现」；16 个维度按语言 / 叙事 / 场景 / 主题分组，每维对照「通用写法」与「这位作者」，列出作者不这么写的、原话依据（第 N 段）与手法。每一句可以点「总带上」（每场都带）或「不用这句」（以后不再用），立即生效、不用重新学习；这本书用在当前作品上之后，每一维还可以设「重点 / 正常 / 不学」。再往下是声音习惯（从全书测出来的句子习惯）、章与场的尺度（规划章节与场景时参考）和「起草时不许出现的词」：本书专名学习时自动识别（只收人名、地名、组织名和作者自造的词），起草时要求避开，也可以自己加；识别错了的普通词可以逐个去掉，去掉的词重新学习也不会再加回来。
3. **用于作品**：直接把这份文风用于当前作品（不经待办）。按钮是 `用于《作品名》`；作品已经用着另一本书时是 `改用这本`（那本的设置保留，换回来还在）；改了设置点 `保存设置`，不用了点 `解除`。三项设置都会以已知方式改变起草时带上的东西：参考方式（`全面模仿`：原文样例 + 文风卡 + 声音习惯，推荐；`只用原文样例`、`只用文风卡`：对照或不发原文时用）、样例窗数（0–16，默认 12，旁边是按这本书实测的字数）、起草方式（`作者手笔直起`，推荐；`先中性后润色`：阅读对照）。导入时选了「起草不发原文」的书只能用文风卡。页面也列出这份文风还用在哪些作品、某一场或某个角色上。**本场预览**：选当前作品的一场、点 `看这一场`，看它起草时会拿到哪些样例（第几章 · 章首 / 章末、梗概、场面 / 情绪 / 手法标签、主要段落类型，可以展开读原文）以及文风卡、声音习惯、防照搬红线的全文和字数。

左栏下方的「参考书活动」列出正在跑和刚结束的段落分类、学习文风、对照检查作业：进度、阶段、已用与预计时间，在跑的都可取消（对照检查也可以），失败或取消的可继续（正文太短这类不可续跑的失败只给「重新学习」，另可「仍然学习」）。这些作业在服务端持久保存，刷新页面或后端重启之后会接着跑。

**起草时发生什么**：用于作品之后，AI 起草台的每一场先用作者的手笔写首稿（样例放在离输出最近的位置）；系统拿这本书自己的片段量一量首稿像不像，在作者的正常范围内就直接用，越界时只改不像的那几个维度、改完再量，不更像就保留首稿；软质检按参考作者评审，补丁改得不更像就退回。进正文的每一条路径都过抄袭门：与参考书原文连续 12 字以上相同的文字不能进正文，系统会告诉你是第几字到第几字，正文不动；用了本书专名只提醒、不拦（是参考书的专名就换掉，普通词被误收就到文风画像里删掉）。

**对照检查与「像不像」**：风格参考的第四步「对照检查」可以贴一段文字（最多 6 万字）或选本作品的一场，后台跑完后说明它在参考作者自己的段落里排第几（百分位，越低越像）、在不在作者的正常范围内、越出范围的地方（白话短语）、评审按 16 个维度给的分与一句说明，抄袭检查只给计数，不显示原文。AI 起草台证据栏的「像不像」面板显示这一场首稿的名次、风格步做了什么（首稿已在范围内没有再改 / 按几个维度定向修改并采用 / 修改没有更像保留首稿）、补丁是否退回和终稿读数，也可以对当前正文「对照检查」。成稿中心每一场终稿带一个像度角标，页头写明多少场在作者范围内；书用于当前作品时，「文风画像」页还有这部作品的像度趋势与每个维度的均值。

风格参考严格依赖模型：没有接入模型时导入、重新分类、学习文风、对照检查都会直接拒绝，并给出「去设置模型」，不存在启发式或离线兜底。「仅本机模型」的书，只有在这一步用到的模型确实是本机模型（如 Ollama）时才能处理；用云端模型时请换一档范围重新导入。现行技术说明见[风格参考](style-reference.md)。

### 待办

待办卡可能来自内容安全、来源安全、QC、后台任务或资料派生。处理前阅读证据、影响对象和动作说明。卡片消失只表示当前指纹已解决；目标状态变化后，风险可能重新出现。

### 资料

资料库保存人物、世界、事件、关系和时间线等结构化信息。会影响生成的资料应经过作者确认；测试夹具不会进入正式运行库。

## 5. 冲突、失败与恢复

- 写作保存遇到 `409`、离线、配额失败或 AI 覆盖风险时，工作台会创建浏览器本地恢复记录。
- 全局 `同步与恢复中心` 可比较差异、导出、重试、恢复或删除记录。
- 恢复记录只存在于当前浏览器配置和站点存储，不跨浏览器、设备或无痕会话，也不是服务端备份。
- `/live` 成功只说明进程存活；排障与部署探针应同时检查 `/ready`。
- 后台任务会尝试恢复可安全重放的场景和章节任务；风格参考的段落分类、学习文风与对照检查是持久作业，后端重启后会自动接着跑。这不等同于分布式队列或灾难恢复。

遇到问题时按以下顺序处理：

1. 查看页面上的稳定错误码、请求 ID 和建议动作。
2. 检查 `/ready`，确认数据库迁移和必需结构就绪。
3. 检查 `.codex-run/` 中的实际端口和日志。
4. 在恢复中心保护本地稿件后再重试。
5. 仍无法恢复时停止服务并备份数据库，不要直接删除运行库。

## 6. 数据、重置与网络边界

`reset_author_state` 会批量删除作者态项目和运行产物，不是首次启动步骤。先备份，再 dry-run：

```powershell
cd backend
python -m novel_system.tools.reset_author_state
python -m novel_system.tools.reset_author_state --execute --yes
```

后端默认只接受回环请求。远程模式使用的共享 token 不是登录、RBAC 或租户隔离；前端构建变量也不能被视为对浏览器用户保密。完整配置见[运行安全与资源边界](runtime-safety.md)。
