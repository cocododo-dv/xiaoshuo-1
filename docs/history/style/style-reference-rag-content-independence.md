# 风格参考 RAG v2：内容克制检索

## 结论

旧版 RAG 的正向排序依赖 query 与参考片段的字符重合，因此更容易召回“写了同一件
事”的段落，而不是“以同一种方式写”的段落。v2 将正向检索键替换为可解释的风格
签名，并把原文隔离为召回完成后的注入载荷。

## 运行链路

1. 合成画像或应用画像时，为句、段、场景三个粒度抽取风格签名。
2. 向量库只索引私用区风格分箱 token，不索引原文、题材词、专名或原文 n-gram。
3. ANN 只负责扩大候选池；候选随后按连续风格距离重新精排。
4. 风格距离由句段形状、标点节奏、虚词、代词和文字系统比例构成，各组独立加权。
5. 原文二元组重合只能降低候选分，不能产生任何正向加分。
6. 最终分数限制在 `[0,1]`，低于配置阈值的片段不进入提示词。

原文仍保存在本地 collection metadata 中，因为最终提示词需要展示参考片段；它不会
进入正向检索键。Strategy C 的既有“禁止照抄或近似复刻”红线保持不变。

## 升级与失败策略

- collection 名包含 `v2`，与旧版原文索引物理隔离。
- 新画像在 synthesize 时建索引；旧画像在 apply/re-apply 时自动、幂等补建。
- 三个 collection 全部写完后才写 completion manifest；任一 collection 或 manifest
  缺失都会触发完整重建，失败的半成品不会被误判为可用索引。
- 读取到缺签名的旧文档时直接忽略，不静默退回内容相似检索。
- 向量后端不可用或重建失败不会阻断合法的画像应用，响应中的 `rag_index` 会给出
  `ready`、`rebuilt` 或 `skipped` 状态。

## 冻结合成 A/B

冻结清单位于 `config/evals/style_reference/rag_content_independence_v1.json`，包含句、
段、场景共 6 组对照。每组都有：

- 不同题材、相同风格的目标项；
- 相同题材、错误风格的干扰项。

执行：

```powershell
$env:PYTHONPATH = "backend/src"
python -m novel_system.tools.style_reference_rag_ab
```

当前冻结结果：旧字符覆盖控制组 `style_hit@1 = 0/6`，v2 处理组
`style_hit@1 = 6/6`，干扰项命中率由 `100%` 降为 `0%`。报告固定标记
`human_verified=false` 和 `policy_evidence_eligible=false`；该结果证明“机制不再被
题材词主导”，不证明读者会把生成文本认作特定作者。

## 仍需由后续阶段解决

- 风格签名是确定性结构特征，不覆盖意象网络、叙事伦理、潜台词等高阶风格。
- 合成对照不能替代隐藏作品、跨题材生成和真人双盲偏好评审。
- 对在世作家或受保护作品，应以高层特征描述和用户有权使用的文本为边界，继续执行
  反抄袭检测，不能把“更像”解释成可复制独特表达。

下一阶段把这一召回结果接入统一风格契约，并让生成、评分、候选重排和反馈记录使用
同一套可追踪上下文。
