# 风格参考动态模仿 v2 设计与实施记录

日期：2026-08-20

## 1. 结论

风格参考不是“内置若干作者模板”，而是一个对任意用户参考语料动态建模的系统。
鲁迅、朱自清只存在于隔离的公版跨内容基准中，不是生产路由、作者白名单或可选风格。

本轮将目标从“命中几个易统计的指标”改为四个互相制衡的目标：

1. 参考风格的可辨识机制得到保留；
2. 原场景事实、因果和人物连续性不丢失；
3. 不复制参考原句、专名和独特意象；
4. 成文自然，不能靠凑段数、凑标点或机械复读获得高分。

所谓 AI 文本检测器不作为产品成功指标。相关研究已经表明检测结果会受模型、文本长度、
改写和分布变化影响，不能稳定等同于“是否由人写作”。系统只优化可审计的风格忠实度、
自然度和内容安全，不提供规避检测器的承诺。参考：[Sadasivan 等人的检测可靠性研究](https://arxiv.org/abs/2303.11156)。

## 2. 动态风格链路

```text
任意作品或文本合集
  → 四层十六子维度抽取 + 可复算统计
  → reference_basis（绑定本次 book/checksum，不绑定作者枚举）
  → 冻结运行时风格契约
  → 抽象写作机制 + 软分布指导 + 禁止复制规则
  → 风格候选生成
  → 事实/长度/正文完整性硬门
  → 文学缺陷门与一次受控修复
  → 隐藏风格距离、自然度和抄袭审计
  → 采用或回退
```

`reference_basis` 固化以下来源事实：`book_id`、`source_kind`、`text_checksum`、
有效字符数和段落数，并明确 `mode=reference_derived`、`fixed_author_allowlist=false`。
所以每次画像都由实际导入文本派生，作者名称只是可选元数据，不参与风格路由。

## 3. 本轮已实施

### 3.1 生成侧不再看到精确配额

- 将“量化硬锚点”改为“风格分布指导”；
- 精确均值、方差和容差留在 Profile、候选审计与隐藏评测中；
- 生成提示只看到“短句主导”“长段舒展”“换段适中”等粗粒度倾向，以及相对偏高/偏低；
- 问号、分号、省略号、破折号等单一标点密度不再注入生成提示；
- 二次修复不再收到目标段数或标点数量，“分号不足”不再触发主动补分号；
- 基准新增精确配额泄漏守卫，旧硬锚点文案一旦重新进入 `STYLE_REFERENCE` 块即失败。

这样避免生成器与评分器共用同一把尺子，也避免看似更像参考、实则只是机械凑统计的文本。

### 3.2 文学质量门从“总分不下降”升级为“目标缺陷确实消失”

风格稿门控现覆盖模型腔、意象同质、动作复用、句法单调、虚假澄清、总结式结尾、
说明式对话、装饰性意象、动机过度解释、虚假诗意收束和自我复读等风险。

叙事距离、刻意回环、反复意象和反思式收束不被写成统一禁令：它们必须服从参考语料与
场景功能。自动自然度分只统计高置信机械缺陷，不把某一种审美偏好伪装成“人类写法”。

一次受控修复只有在至少减少一个原触发维度，且不新增或加重其他目标维度时才可接受。
旧逻辑只比较总风险数，可能把一种缺陷换成另一种缺陷；该漏洞已封闭。

精确同句复读采用高置信规则：同一实质句出现三次及以上才进入自动硬风险；两次回环可能是
首尾照应、人物口头禅或作者有意选择，不自动抹平。

### 3.3 隐藏评测与画像生成解耦

- 隐藏文体分类器排除 Profile 构建所用的 `MetricsEngine` 特征族；
- 继续使用未进入生成链路的整篇作品留出集；
- 新增风格提示精确配额泄漏门；
- 新增正文完整性与高置信机械复读硬门；
- 新增风格稿相对中性稿的自然度非退化率；
- 自动报告明确标注 `human_judgment_required=true`，不把自动距离冒充审美结论。

## 4. 验收口径

自动基准必须同时满足：

- 所有必需事实完整保留；
- 所有样本符合长度带；
- 无参考正文复制；
- 提示不含隐藏作品、作者身份或精确风格配额；
- 风格稿不是中性稿的空白/标点改版；
- 隐藏风格归因和成对对比达到冻结阈值；
- 风格稿无高置信自然度硬失败，且多数样本不比对应中性稿退化。

但上线结论还必须经过跨题材盲评。盲评者只看匿名候选，分别评价：风格贴合、自然度、
内容保真、人物声音和愿意继续阅读程度。自动分数不能替代这一关。

## 5. 开源项目融合决策

本轮不直接合并任何“AI 小说整仓”。当前短板位于风格控制与评测边界，而不是缺少另一个
编辑器、工作流或提示词集合；整仓融合会引入重复状态、模型路由和许可证风险，且无法证明
结果更好。

可借鉴但应做成隔离适配器的方向：

- [STRAP](https://github.com/martiansideofthemoon/style-transfer-paraphrase) 的“先内容归一、再恢复目标风格”可作为实验臂，适合验证内容与风格解耦，不直接替换长篇场景主链路；
- [TinyStyler](https://github.com/zacharyhorvitz/TinyStyler) 的少样本作者风格嵌入与多候选过滤可作为未来的可选 reranker/embedding 实验，不把其英文短文本结论直接外推到中文小说；
- [STEL](https://aclanthology.org/2021.emnlp-main.569/) 一类内容去耦风格评测适合继续增强隐藏评测；
- [LLaMA-Factory](https://github.com/hiyouga/LlamaFactory) 只作为未来本地 LoRA 训练后端候选。只有用户拥有足量、权利清晰的语料，而且 LoRA 实验在盲评中显著胜过当前动态 Profile、内容与自然度均不退化时，才允许进入可选路径。

任何外部方案的接入顺序固定为：离线实验适配器 → 同一冻结基准 A/B → 匿名人工盲评 →
通过后再做可关闭的生产开关。不得先合并代码、再寻找收益。

## 6. 当前边界与下一步

本轮完成的是架构和确定性门控修复，定向后端回归已通过。新的提示版本仍需跑一次真实模型
跨内容基准，并完成盲评，才能对“比上一版本提升多少”给出可信数字。

后续优先级：

1. 运行新旧提示同模型、同温度、同场景的盲化 A/B；
2. 将用户对成稿的真实编辑差异提炼为项目私有偏好，而不反向污染参考语料事实；
3. 扩大到至少四种作者/体裁组合，避免两位公版作者造成的评测过拟合；
4. 只有动态 Profile 达到瓶颈后，再试风格 embedding 或 LoRA 实验臂。
