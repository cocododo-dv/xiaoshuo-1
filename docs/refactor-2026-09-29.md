# 2026-09-29 全系统重构：给作者的说明

这次重构把前后端从头到尾理了一遍：拆大文件、删死代码、收重复、补测试、提速。默认原则是**行为不变**——你在界面上会注意到的
变化，主要是你在 2026-09-30 拍板批准的那些（下面按批准条目编号列出），另有几处是「让产品做到它本来就声称的事」的 bug 修复；
此外，2026-09-24 那一轮风格参考「清理与优化」做完后一直没部署，这次随重构一起上线（见下面「风格参考」一节）。
条目的完整理由与执行细节记在重构工作区，这里只写你会看到什么。

## 1. 你会看到的变化

### 构思（雪花十步）

- **07 长篇大纲里的章节表变成只读镜像**（#18a）：章名、章摘要、章界、灾难标记只在「整理章节结构」的分章面板里改；07 每一章行尾的
  「改名」直接打开面板并对准那一章。前面的步骤还没确认、「确认写入」点不动时，面板上有「只保存章表」，章表也有地方存。分章策略
  改叫「倒进现有章表」「现有章表 · 均分」。章名改的地方从三处变成两处：分章面板与章节编排，改哪边两边都跟着变。
- **「历史」页签能看到服务器上保存的每一版**（#24a）：每次确认、AI 生成、整步清空（抹空保护）、从历史恢复都会留一版，可以预览、
  直接恢复，换了浏览器也找得回来。
- 第 9 / 10 步点「已复核」时，过期的场景计划一起复核，不会再卡住「整理章节结构」（#24a）。
- 导出与「引用上下文」改成带栏名的中文分步文本，不再夹着内部 id 与英文枚举（#18b）；构思里的确认框换成应用自己的确认框（#18c）。
- AI 补全人物表时不再逼配角填满：原著只要求主角与对手完整，配角留白是合法的（#16b）。
- 手加的人物在服务端带上作品前缀存储，两部作品里同号的人物不再互相改名（#16c；界面上仍显示原来的编号）。
- AI 建议分章只挪先后放错的那一场，不会因为一场放错就重排一整段（#17c）。
- 没接好模型时，「AI 分诊」直接说没接好、给「去系统配置」的门，不再拿规则诊断冒充 AI 结果（直接修）。
- 构思页几处不在刻度上的窗口宽度断点挪正了（截图对比后挑的方向，#26c）：1181–1280 宽时右栏改成抽屉（点 ⓘ 打开），编辑区宽出一截；
  窄于 900 时十步列表收起，翻步用页脚的上一步 / 下一步或 ⌘K。其余页面的同类断点以后逐页处理。

### 风格参考（2026-09-24「清理与优化」，这次一起上线）

- 对照检查可以取消：页内与活动清单里排队 / 进行中的检查都有「取消」，轮询超过 3 分钟后放慢。
- 学习失败后按能不能续跑给「继续学习」或「重新学习」；参考书正文太短时给「仍然学习」。
- 样例窗口的标签改成按 16 维打（标签 v2），所以部署后要对正在用的参考书点一次「学习文风」（见第 2 节）。
- v3 之前的旧画像归档、旧版风格待办行删除（迁移 0092，只改数据）。

逐条细节见[风格参考 v3 记录](style-reference-v3-2026-09-23.md) §8。

### 章节编排

- 章级的「张力 / 线索 / 伏笔 / 章级视角·时间·地点·入口·出口」这些没有任何地方能填的字段删了；「AI 体检」与「AI 编排方向」
  改读各场的真实数据（视角疲劳看前几章各场的视角，承接错位看上一章最后一场和这一章第一场，「压力没有升级」看这一章各场的冲突、
  挫折和章节蓝图），「伏笔逾期」这一项去掉（#17a）。
- 你亲手写的章节蓝图不会因为构思设计或参考书改动而作废，只在蓝图旁提示「这份蓝图写好之后，构思或参考书又改过」，蓝图照旧用于起草（#17b）。
- 章节编排的 AI 在没有模型时一律直接说明、不给假结果；另有一份不需要模型的「待补清单」（直接修）。
- 章节状态的判定在主页、成稿中心、章节编排三处统一成一条规则；模型节点的中文名只有一张表；戏剧卡导出的小标题用编辑器里的叫法（#19）。

### 写作台

- 选中正文做 AI 改写，一次最多 2000 字：选区更长时直接提示「选区太长（N 字），请分段改写」，一个字都不发、不删（#20a）。
- 跨段选中改写时，改好的版本按段落换回原处，「还原原文」能把原来的几段原样拼回（#20b）。
- 另一台设备或另一个标签页同时改过这一场时，编辑器换成服务端的版本，你本机没存上的每一稿都放进「同步与恢复」并提示——两边的字
  都不会丢（#20c）。保存改成一台状态机：一场同一时刻只有一次保存在路上，存不上的留在本机、下一次保存时重发。
- 「AI 续写」生成新的一组三条时，上一组标成已替换，只留最新三条；多段的续写候选保留分段（#7）。
- 版本对比：自动保存的快照每 5 分钟至多留一份，提升成权威正文的那一版永远留着；版本列表分页，「更早的版本」接着往下取（#8）。
- 全书字数 = 各场实际字数之和；今日字数、连写天数不变（#9）。

### 成稿中心

- 手写或逐场采纳的章节以前永远无法定稿，现在可以了（#10，bug）；「已通读」并进了「确认定稿」：批准对话框里一个勾选框 +
  「确认通读并批准」，服务端把确认绑定到你读到的那一版正文的哈希，仍按章依次定稿。
- 「刷新章节汇总」按钮删了（它调用的接口早已不在，每点一次都报错）；章的正文改为读取时由各场当前终稿现拼，删场、恢复、搬章
  之后自动跟上（#21）。
- 「采纳并归档」与成稿中心「晋升」做与起草流水线相同的确定性收尾（「像不像」读数、章汇总、卷汇总）（#22）。
- 正史事实按人物名 / 别名匹配，摘要里显示名字而不是内部 id；「提取」分段读完整场（#14）。

### 质量与诊断

- 「必须出现」的内容在起草、质检和定稿闸都按组逐一检查：每一组都要写到（组内写成「A|B」的，写到任一即可），不再是沾上两个片段就算满足（#11）。
- 受保护专名处处只提醒；与参考书原文连续 12 字以上相同是唯一会拦下正文的检查（#12）。
- 章组复审也按绑定的参考书校准（#13a）；软质检给出的风格偏差写进修补简报，补丁知道照样例改哪一段（#13b）；
  文学质量里永远为空的「有效留白」维度删掉，21 维变成 20 维（#13c）。

### 成本看板与设置

- 成本看板以 token 为主：只有在 `config/pricing.yaml` 里写了单价的模型才折算金额，其余标「未定价」，不再用占位价编美元（#4）。
- 六道只能用环境变量打开、默认全关的全局额度闸删了，「全局用量」卡只显示读数（#3a）；场景级预算闸保留（默认关）（#3b）。
- 「设置 · AI 模型」保存的配置只记你为每个节点选的服务与模型，其余参数取代码里的默认值——修好的默认值随发布直接生效，你的选择
  一个不丢（#5a，迁移 0096）。四个从不调用模型的「保留节点」删掉（#24b，设置页本来就看不到它们）。

### 报错与后台

- 后端报错改成中文说明，按错误码给出（#27）。
- 数据库结构落后于代码时，页面统一提示「数据库结构需要升级：请重启后端（启动脚本会自动升级）」（#28）。
- 「防重复提交」的缓存只留 72 小时，部署时压缩一次数据库——按部署前的估算，库会从四百多 MB 降到几十 MB，备份快得多；对照检查的作业记录 30 天后删
  （读数留着），每本书的分类 / 学习作业只留最近一次（#23）。

## 2. 部署之后你要做的

1. **刷新**每台设备上开着的工作台页面，在新界面里改任何东西之前（前后端一起换了版本；没刷新的旧页面会把它手里的旧构思推回服务器）。
2. **对正在用的参考书点一次「学习文风」**：样例窗口的标签换了新版本（改成按 16 维打），这一次学习会给全书片段重打一遍标签
   （几十次模型调用）；之后再学习只补新片段。
3. 想在成本看板上看到金额：在 `config/pricing.yaml` 写上你用的模型的单价（格式见文件开头的注释），保存即生效，不用重启。

部署本身（停服 → 备份留档 → 升级数据库 → 压缩 → 同步提示词 → 启动）的顺序见[数据库迁移](migrations.md) §4。部署前的那份备份
永久保留：压缩会清掉的重放缓存里，有一些构思草稿的中间状态只存在于那里。
